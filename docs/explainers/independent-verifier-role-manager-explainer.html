Miah is a piece of software that supervises AI agents doing planned engineering work: it validates the plan, dispatches specialist agents, collects evidence of what they actually did, and decides when a unit of work is done. This explainer covers one change to Miah — the one delivered in pull request #9 — in plain language.

The change in one sentence: Miah used to both run the checks and judge the results. Now it only runs the checks. A separate specialist — the verifier — does the judging, and anything that needs human judgment goes to a human.

The idea: separate the referee from the player

The principle behind the change is old and simple: the person who decides should not be the same mechanism that performs the work. In a sport, the referee is not on the team. The same logic applies to AI-run work — if the software that coordinates the work also grades the work, there is no independent second set of eyes on its own evidence discipline.

Miah had been doing both jobs: it ran verification checks (the "sensing") and it also mechanically graded the results (the "judging"). That concentration of judgment is what this change removes.

Why this matters

Three concrete problems motivated the change:

  • Concentrated judgment. When the coordinator also grades, nobody independently checks the coordinator's own evidence discipline. A verifier that always passes is worse than no verifier — but so is a supervisor whose pass/fail calls are never questioned by anyone.
  • Checks written after the work. Previously, verification checks could be written after implementation, which lets the checks quietly chase whatever the work happened to do. The change makes the checks exist first: the plan now carries a frozen "verification contract" for each unit of work — the specific checks the work will be graded against — approved before any implementation starts.
  • No second set of eyes. The grading decisions needed an independent reviewer. The change folds the old "reviewer" role into a single verifier specialist with the authority to grade everything — and to flag anything as needing a human.

How it works now

1. The checks are frozen before the work

At planning time, each unit of work gets a verification contract: the exact checks (commands) it will be graded against, plus stable identifiers for each acceptance criterion. The contract rides inside the immutable plan snapshot. A unit without a contract is refused admission up front — fail closed. Changing a contract after approval is treated as a scope change requiring operator approval.

2. Miah senses, the verifier judges

During execution, Miah runs the frozen checks and collects evidence (build outputs, test results, file changes) into a tamper-evident, hash-chained record — the custody chain. It then dispatches the verifier specialist, read-only, with the evidence package and the frozen contract. The verifier grades every non-human criterion and returns a structured envelope with one grade per criterion: pass, fail, or ungraded, each with a stated basis and pointers to the evidence it relied on. Miah itself produces no grade.

3. Human judgment goes to a human

Three paths send a criterion to the operator:

  • Criteria declared human tier in the plan are graded by the operator from the start.
  • The verifier may flag any criterion as warranting human judgment.
  • Judgment grades only carry authority when the verifier's profile clears a configured calibration bar; otherwise the criterion stays ungraded and escalates.

An operator grade is the only thing that satisfies a human-tier criterion. Grading is now criterion-level: resolving one criterion can no longer accidentally accept a whole unit while another criterion is still unsatisfied.

4. Failures never waste work

If a verifier attempt fails (bad envelope, missing evidence, unreachable workspace), it counts as a verifier attempt — it never spends a builder's implementation attempt. Runs remain resumable: a crash mid-verification resumes from the journal and evidence, not from scratch.

Honest caveats

What is not yet done:

  • Tester dispatch. A separate "tester" role is specified but not yet built. The verifier currently grades an evidence package that includes no tester outputs; grading proceeds correctly without them, and tester dispatch is future work.
  • Two end-to-end tests run only in CI. Two integration tests require a live agent daemon and cannot complete in this local environment; they are committed and will be exercised by the CI pipeline.
  • Two small follow-ups were filed as issues (an unused import to clean up; a defensive hardening on an older code path) — neither blocks this change.

The bottom line for a manager

This change makes Miah's quality bar independently enforced: the checks are agreed before work starts, the grading is done by a separate specialist with evidence to show for every call, and anything that needs human judgment is escalated to a human instead of being decided by the machine. The work went through implementation, simplification, two independent review passes, and a formal merge-readiness verdict — 7 review findings found and fixed, none remaining — and is ready to merge.
