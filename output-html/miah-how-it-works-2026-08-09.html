How Miah runs a plan

Miah is a command-line supervisor that takes one approved plan and drives it to completion through specialist agents — with everything it does recorded to disk so it can survive crashes, and nothing decided without evidence. This explainer follows the operational path: how you use it, what happens at each step, and the design underneath.

The idea in one breath

Core loop

One immutable plan

You approve a plan once. Miah snapshots it, then executes that exact snapshot — unit by unit, in dependency order — with agents that work in isolated worktrees.

Evidence, not prose

Verification is mechanical

Builders and reviewers are separate agents on different model families. Verdicts only count when backed by harvested artifacts — diffs, exit codes, test output — not agent claims.

Disk-first

Crash-safe by construction

Every event is appended to a journal on disk. A kill at any moment is recovered by replaying the journal — proven by kill drills that assert byte-identical state.

You stay in control

Operator gates

Miah has bounded autonomy: escalations pause for your decision, and the final approval package is yours to accept, rework, or reject.

The operating loop, end to end

Five stages. You drive the first, the last, and every pause; Miah drives the middle with strict limits on how long it will push on its own.

1 · Admit miah start plan.md — preflight, probe, snapshot, journal
→lease + run_start
2 · Drive miah run — dispatch builder → harvest → dispatch verifier
→per unit
3 · Gate all accepted → approval package, AwaitingApproval
→your call
4 · Complete miah approve — or reject/rework/amend
↻resume anywhere
5 · Escalate stuck → Attention, miah resolve

The five stages loop through a six-phase state machine (below). If the machine dies mid-run — power cut, crash, whatever — the next miah run replays the journal and continues from the exact same byte-level state.

Use cases, walked through

Five common situations and what Miah does in each.

“I have a plan file — get it running”

miah preflight plan.md runs the pure checks: every requirement traceable to a unit, no cyclic dependencies, no cross-unit deliverable conflicts, tiers recognized, acceptance criteria present. If it fails, you get a list — nothing is admitted half-checked.

miah start plan.md goes further. It runs the substrate probe: a fail-closed capability check against the agent platform (Paseo). If a required capability is missing, admission refuses — Miah would rather not run than run dishonestly. On success it writes the run store: the immutable plan-snapshot.v1.md, units.json, a manifest carrying the admission-time config snapshot (R80 — a run keeps the config it was admitted with, even if you edit the file later), the lease, and the journal opened with run_start and an Admitting phase transition.

Design underneath. Admission is the first trust boundary: the plan snapshot is immutable, the probe fails closed, and the run's config is fixed at admission — so a run in progress can never silently change its own rules mid-flight.

“Run it until it's done”

miah run starts the driver loop. For each eligible unit, in dependency order:

Dispatch a builder

An implementation agent (deepseek-v4-flash by default) works in an isolated worktree on its own branch, and commits its take. It is given the plan unit, its acceptance criteria, and the run's guardrails — nothing else.

Harvest evidence

When the builder terminates, Miah harvests artifacts — the diff, exit codes, test output — and chains them into a hash-linked custody chain. Prose from the agent is never evidence.

Dispatch a verifier

A different model family (glm-5.2 by default) audits the unit against the plan's per-unit G-criteria, re-running gates from disk — never from the builder's chat context. Verdicts are binary: PASS with evidence, or FAIL naming the missing criterion.

Accept or rework

PASS → the unit is accepted and its deliverables integrate into the canonical worktree. FAIL → the unit goes back for another take, up to bounded limits (3 takes / 2 rework cycles, configurable). No-progress detection (3 unchanged polls) and a dispatch deadline (15 min) keep a stuck unit from spinning forever.

Design underneath. Cross-family verification hedges shared-training blind spots; calibration is the actual authority — a checker profile only clears the bar with ≥15 pre-labeled cases, >14/15 agreement, ≤2 false blocks, zero false-pass floor. And everything is journaled: a verifier that dies mid-audit is re-run fresh from disk.

“A unit keeps failing”

When a unit exhausts its takes or rework budget, or no-progress persists, Miah raises an escalation — a first-class journal event with a stable id (esc-<seq>), pauses the run, and moves the state machine to Attention. The driver stops dispatching; your move:

miah status shows the run phase and pending escalations. Then miah resolve <esc-id> --decision approve|rework|deny:

DecisionWhat happens
approveOperator authority accepts the escalated criterion: its gap is closed and the unit is marked accepted (integration still runs, per R89).
reworkThe unit is durably marked for re-dispatch; the run resumes and sends it back to a builder.
denyCloses the escalation without changing unit state. If the blocking condition still holds, it re-raises on the next miah run — deny dismisses, it doesn't hide.

Design underneath. Bounded autonomy: two consecutive verifier FAILs or a broken dependency also stop the loop and escalate to you. The escalation journal trail (escalation_raised → operator_decision → escalation_resolved) is a complete, replayable record of every judgment call.

“Everything is accepted — now what?”

When all units are accepted, Miah writes the approval package: per-unit evidence pointers, acceptance records, gap close reasons, usage totals, snapshot hash, and run duration. The run parks in AwaitingApproval. Your options:

CommandEffect
miah approveRun → Complete.
miah reject --rework U2,U5Marks units for re-dispatch; the R67 resume re-opens the gate (AwaitingApproval → Ready) and the run continues — the marking is durable, so it survives restarts.
miah reject --endTerminal rejection.
miah amend <plan>Admits a new plan version; only affected units are re-dispatched. The config snapshot and amend trail are journaled.

Design underneath. The state machine is state-aware, not just a static transition table: AwaitingApproval → Ready is legal only when units are actually marked for rework (R67) — a lesson paid for by a real bug where the marking worked but the resume didn't.

“The machine died mid-run”

Kill Miah at any moment — mid-dispatch, mid-append, mid-harvest. The next miah run:

Acquire the lease

The admission lease (lease.lock, heartbeat + TTL) is taken with stale-takeover rules: a dead holder's lease can be reclaimed, but a live one is never stolen.

Replay the journal

Every event since the last snapshot (taken every K=50 events) is replayed to reconstruct derived state — byte-identical to what a driver that never died would see.

Reconcile in-flight work

Dispatched intents without a recorded result are reconciled: the adapter is queried, terminated work is harvested, live work is polled, and nothing is double-dispatched (idempotency keys, R37).

Continue

The driver resumes exactly where the journal says it was. This is the kill drill: a verification suite that kills the process mid-run and asserts byte-identical reconstructed state — the plan marks it “non-negotiable”.

Design underneath. Disk-first supervision: the journal is the source of truth, snapshots bound replay cost, and the lease arbitrates concurrent drivers. Your chat transcript with Miah is disposable — the state never lives only in a session.

The state machine at a glance

Eight phases. The spine runs Admitting → Ready → Implementing ⇄ Reviewing → AwaitingApproval → Complete. Two pause states interrupt it (gold = waits for you), and Stopping is reachable from anywhere via miah stop.

Admittingpreflight · probe · lease · run_start
Readylease held, no work yet
Implementingbuilder dispatched
Reviewingverifier auditing evidence
AwaitingApprovalapproval package · your call
Attentionescalation · your call
Stoppingoperator stop
Completeterminal · or rejected

Every transition is a journaled phase_transition event, so the phase is always derivable from the durable record — never from memory.

What keeps the loop honest

Evidence

Custody chain

Every harvested artifact is SHA-256 content-hashed and linked via prev_hash headers. A broken link is an evidence gap — a FAIL, not a footnote.

Gaps

Problems can't vanish silently

Gaps are first-class events (gap_recorded / gap_closed). An acceptance that supersedes open gaps must journal explicit close events first — or the approval package is incomplete.

Calibration

Reviewers earn authority

A verifier's verdict counts only after its profile clears the calibration bar (≥15 corpus, >14/15 agreement, ≤2 false-blocks, zero false-pass). Cross-family contrast is a hedge; calibration is the authority.

Fail-closed

Admission refuses, never fakes

The substrate probe fails closed: missing agent capability → no run. Known platform gaps (per-agent max-duration, post-termination immutability) are honestly refused rather than papered over.
