Grounding Context

Codebase context

Miah is in Phase 2 (Planning) — no code yet, eleven docs-only commits, working tree clean. VISION.md defines the product: a resumable plan supervisor that coordinates specialist agents to execute one immutable approved plan, with independent testing, review, durable evidence, bounded autonomy, and operator approval gates. STRATEGY.md frames winning as "maximizing trustworthy execution within an operator-defined effort ceiling," across four tracks — plan-faithful orchestration, durable execution/recovery, independent assurance, operator control/visibility — measured by first-pass approval rate, operator effort compliance, plan drift rate, and corroborated proof rate. It is explicitly not an implementation agent or a general orchestrator.

docs/planning-brief.md frames eight open design decisions (D1–D8, dependency-ordered) for ce-brainstorm → ce-plan. The docs/research/ files are decision-free grounding: a substrate (Paseo) capability inventory, a field SOTA digest, ecosystem conventions, and a marker-staged prior-art digest held out of brainstorming.

Pain points / gaps: D1 is the keystone — Miah must outlive any agent session yet harnesses are session-bound. D2: tester/reviewer independence is a context-isolation property, not a role label, and the substrate doesn't enforce it. D4 ("hardest to retrofit"): write-ahead journal, idempotency, leases, resume-with-reconcile, crash-tested recovery all open. D7: threshold numbers are deferred, though research shows they're a runtime budget-predicate mechanism, not config values. Stale README, a session-history probe bug, empty docs/findings/, no testing-runbook.md, and a Paseo CLI contract needing re-verification.

Leverage points: D1+D2 shape everything downstream. The D5 evidence contract (deterministic > calibrated LLM-judge > human grader triage) is the highest-leverage reliability mechanism, measured directly by the corroborated-proof-rate metric. The operator's own authored orchestration preferences (role→model map, cross-family audit, worktree isolation) are a ready-made D2/D8 candidate.

Past learnings

None — no docs/solutions/ store exists, which is expected for a planning-phase repo. The research docs above are the de facto knowledge base; the learning store should be seeded at Phase 3.

External context (web research)

Supervisor/orchestrator-worker is the 2026 default (~70% of production deployments); the orchestrator plans and delegates but never executes, workers are context-isolated. The dominant failure mode of static plans is stale plan, no replanning — Miah's immutability is a deliberate inversion of that trend and must answer it. Durable execution is solved infrastructure: Temporal (event-sourced workflows, replay-based crash recovery, zero-compute waits, continue-as-new), LangGraph checkpointing, Cloudflare durable gates, DBOS. HITL gates are a formal pattern — propose → review → cryptographically-locked payload → execute → outcome-log; approval fatigue is real (~93% rubber-stamp), so exception-only, risk-scored review is the scale answer; approval is not execution. Evidence has formal theory ("Auditable Agents": action recoverability, lifecycle coverage, policy checkability, responsibility attribution, evidence integrity); audit trail ≠ observability. Bounded autonomy ships as deny-first stacks and graduated, evidence-gated dials. No one sells "approved immutable plan + durable evidence + bounded autonomy" as a packaged unit; EU AI Act Articles 12/14 enforcement began Aug 2026, making audit trails procurement table-stakes. Aider's rule: reversible = autonomous, irreversible = gated.

1 · TOP PICK

The durable-run spine — D1 + D4 resolved together

Confidence 85% Complexity High

Miah's supervisor becomes a stateless interpreter of two durable artifacts — the immutable plan snapshot and the append-only journal. Any host (CLI, cron, Paseo agent, tomorrow's shell) can acquire the single-writer lease and drive the run; "resume" is just running the function again, so session-boundness evaporates. The run is a directory of unit-scoped mini-runs: each unit owns its sub-journal, lease, budget, and partial-state termination, with continue-as-new closing long histories. Recovery is reconcile-then-continue — verify every dispatched unit reached a terminal state before proceeding — under a standing invariant: delete everything but the journal, rebuild state from it alone, resume identically. A miah drill command deliberately kills the supervisor mid-run and emits the reconcile report, making crash-testing a unit-test ritual instead of a project milestone.

Basis
direct: planning-brief D1 ("Where does the durable supervisor loop actually live?"); agent-orchestration-research §1.5 ("The thing that needs to survive a crash is not the code, it is the record of what the code has already done"; single-writer lease; write-ahead journal) and §2.9 ("the resume path is exactly where bugs live"); VISION ("Every run is locked to an immutable snapshot"; "A crash or interrupted session does not lose completed work"). external: Temporal event-sourced workflows, LangGraph checkpointing. Four of six frames landed on this shape independently — the strongest convergence in the run.
Rationale
D1 is the keystone decision; making the run the durable entity dissolves the deterministic-process-vs-agent-vs-hybrid choice into a protocol question, and D4's "hardest to retrofit" concern disappears because every loop iteration is by definition a resume. It also makes mid-run harness changes and operator mid-run model swaps free.
Downsides
The journal + lease + reconcile machinery must exist before anything else works; the operator's Paseo substrate kills agents on daemon restart, so the spine must be robust to that reality; higher initial engineering cost than a session-bound prototype.

The evidence spine — D5 as five interlocking layers

Confidence 80% Complexity High

The evidence contract is built as a stack where each layer closes the residual trust gap of the layer below: (1) Harvest — Miah collects evidence itself (diffs, test exit codes, tool-call traces, workspace state) at dispatch boundaries, never agent self-reports; (2) Replay — acceptance is the verification contract re-ran clean in a fresh context, so corroborated proof is countable by construction; (3) Corroborator — one grading ladder (deterministic > calibrated LLM-judge > human) every gate composes; (4) Custody — every artifact carries a full custody chain (producer role, agent ID, take, timestamp, hash) over a hash-chained, HMAC-locked journal, so hearsay (a claim about its own work) is inadmissible and broken custody is refused at admission; (5) Falsification — every acceptance review states 2–3 runnable falsifying checks and records their outputs; only claims that survived recorded refutation count.

Basis
direct: agent-orchestration-research §2.6 ("Evidence = artifacts + traces that Miah collects itself… not agent self-reports"), §1.6 grader triage, §2.7 WORM + cryptographic signature; STRATEGY ("Specialist-agent claims are evidence inputs, not facts"). external: arXiv "Auditable Agents" five evidence dimensions; chain-of-custody and hearsay doctrine; Aider's reversible=autonomous rule.
Rationale
The corroborated-proof-rate metric is the most direct measure of the product's core promise; the spine turns that metric from a post-hoc judgment into a mechanism, and it is the component with the most callers in the product (every acceptance and escalation decision).
Downsides
Five layers is real machinery; LLM-judge calibration is a workload of its own; falsification checks can decay into ritual unless the reviewer has budget to actually run them.
3

The operator-time stack — D6 / D7 / D8 as one autonomy-control design

Confidence 75% Complexity Medium

A single mechanism answers "how much of the operator's attention, when": exception-only approval surface — the operator sees only risk-scored exceptions sized for a 10–30s decision while routine actions auto-proceed within plan-granted autonomy; batch-decision mode — escalations park with their evidence packs, the run continues on safe paths, and the operator resolves the batch at the next natural gate or final approval; attention as the effort ceiling — each run gets a finite budget of escalation interactions, depletion meaning a report-only tail that fails closed; thresholds as a journal-predicate engine — budget predicates over tokens, retries, escalations, corroboration, and wall-clock, evaluated by one engine at every autonomy boundary and calibrated from run cards rather than invented; approval provenance — every operator decision is a structured journal entry with a reason code, linked evidence, and optional conditions Miah auto-closes.

Basis
direct: planning-brief D6 ("Escalations must reach an operator who may not be watching") and D7; VISION ("Routine intermediate decisions remain with Miah"); STRATEGY operator-effort-compliance metric. external: exception-only review as the scale answer, ~93% rubber-stamp approval fatigue, graduated evidence-gated autonomy dials, EU AI Act Art. 12/14 logging-and-oversight.
Rationale
Operator attention is the bounded resource the whole product is built around; today the effort ceiling is a post-mortem statistic — the stack makes it enforced-by-construction and turns approval fatigue from a vulnerability into a measured signal. Three frames converged on it.
Downsides
Auto-proceed needs trust tiers and risk scoring that take calibration to get right; batch-decision mode requires a careful definition of "safe paths"; a fatigue-blind implementation could silently widen gates.
4

The operator-owned amendment path — immutability with an escape valve

Confidence 75% Complexity Medium

The plan document never mutates; only the contract layer (scope, requirements, acceptance criteria) is what actually freezes. When reality drifts, the operator issues a change order — an operator-approved, journaled delta that locks into a new immutable snapshot, with re-approval scoped to the affected units — and every run's record ends with an as-built section: the operator-owned statement of reality-vs-plan that the next run starts from. Immutability applies to the changelog, not the content, and plan drift becomes mechanically measurable: drift is any mutation that is not an approved amendment.

Basis
direct: VISION ("Every run is locked to an immutable snapshot of that plan"; "changes to scope, requirements, or acceptance criteria require operator approval"). external: construction change orders and as-built drawings; stale-plan-no-replanning as the dominant failure mode of static plans — the immutability bet must answer that literature. Four frames converged here.
Rationale
The product's most distinctive decision (an immutable plan) is also its most exposed weakness (staleness); without an operator-owned change route, the escape valve is an abort that throws away banked evidence and progress. The change-order discipline answers the industry objection without surrendering immutability.
Downsides
Re-approval scoping (delta vs whole snapshot) needs definition; a loose amendment mechanism becomes de-facto replanning; the drift metric must distinguish approved amendments from unauthorized mutation.
5

Mechanical independence — D2 made structural

Confidence 75% Complexity Medium

Tester/reviewer independence stops being a role label and becomes a dispatch property: reviewers receive only the unit spec, acceptance criteria, and the harvested evidence pack — builder identity and builder-visible context are redacted; they run in a fresh worktree on a deliberately different model family; and the journal's acceptance entry is written from the reviewer's verification record, not the builder's claim (maker-checker: the checker's record is what posts). Independence becomes a testable property of the pipeline rather than a promise.

Basis
direct: planning-brief D2 ("a tester that shares the builder's context is not independent"); agent-orchestration-research §2.4 (shared-context critique approximates self-correction); ecosystem-grounding (the operator's standing role→model map, cross-family audit, worktree isolation). external: banking dual control / four-eyes principle.
Rationale
Corroboration only means something if corroboration is actually independent; a reviewer who read the builder's outputs is a re-reader, not a check. Making independence a verifiable dispatch property is the structural enforcement D2 says the substrate lacks, and it composes with the operator's already-authored orchestration preferences.
Downsides
Redaction and context-freshness machinery adds dispatch complexity; a reviewer who genuinely needs the builder's transcript to judge gets a weaker hand, so the evidence pack must be complete on its own.
6

Run cards — the compounding artifact

Confidence 80% Complexity Low

Each run ends with one consolidated projection — plan, units, approvals, escalations, evidence links, cost, time, verdict — that is simultaneously the D6 operator surface (the final approval package), the metrics corpus for all four STRATEGY metrics (all measured from the run journal), and the calibration dataset for D7's threshold defaults. After a handful of runs, the cards make the operator's effort ceiling empirically grounded instead of guessed, and each run's validation rules train on what previous runs actually did.

Basis
direct: STRATEGY metrics "measured from final approval decisions in the run journal"; planning-brief D7 ("planning must at least fix the mechanism and defaults"); VISION step 9 (consolidated evidence package). external: auditability cards mirroring model cards.
Rationale
One artifact compounds in two directions — per-run operator value and cross-run metrics/calibration — and it is the bridge to every self-improving idea in the set: the repo's current empty docs/findings/, missing runbook, and absent solutions store can be fed by runs from run one.
Downsides
The schema is load-bearing (UI, audit artifact, and metric dataset in one), so it must be designed before run one or retrofitted later at real cost.
7

Mechanical staging — protect the planning phase today

Confidence 70% Complexity Low

The staged-context protocol keeps the predecessor's prior-art digest out of brainstorming via a DO-NOT-READ marker — a convention that depends on every agent in the session obeying it, and one unrecorded read silently contaminates every decision the later adversarial pass tries to validate. Enforce it mechanically: relocate docs/research/prior-art-paseo-supervisor.md to the git-ignored tmp/ directory during brainstorming so no tool or agent can anchor on it, and let the cross-check step restore it.

Basis
direct: planning-brief prior-art handling (marker-staged digest, "open only at step 2"; "The plan must never silently inherit prior-art decisions"). reasoned: a marker is a promise by an actor whose context includes the file; anchoring is exactly what the cross-check and anti-sycophancy passes exist to catch, so it is the one step of the protocol that can fail silently and undetectably — a file move removes the failure entirely.
Rationale
The entire decision-quality apparatus of the planning phase (independent research, cross-check, adversarial probe) is undermined by one unrecorded read; mechanical enforcement is nearly free and makes the marker unbreakable.
Downsides
Only relevant to the current planning phase; adds a small ceremony step to the brainstorm workflow.
